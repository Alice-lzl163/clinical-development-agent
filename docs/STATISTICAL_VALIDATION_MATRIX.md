# Statistical Validation Matrix

## Purpose and decision rules

This matrix evaluates statistical fitness, not code recoverability. Historical source proves that a branch existed; it does not validate the method, its label, or its numerical results. Package and function names recommended below were checked against official R/CRAN documentation listed in the source register. A recommendation is still subject to the validation gates in `VALIDATION_PLAN.md`.

Validation grades:

- **V1** — established method implemented through a mature, widely used statistical package or independently validated algorithm.
- **V2** — standard analytical method, but the implementation requires independent benchmark validation.
- **V3** — approximation that may be acceptable when explicitly labeled and its assumptions are appropriate.
- **V4** — surrogate or heuristic implementation that does not fully represent the advertised method.
- **V5** — historically mislabeled, incomplete, or unsuitable for production; do not migrate the historical implementation.

Migration actions mean:

- **KEEP** — retain the package/function method, but it must still pass production gates.
- **KEEP_AND_VALIDATE** — retain the approach provisionally and establish independent numerical evidence.
- **REPLACE** — retain the test key only; replace its historical numerical method with the stated production method.
- **REDESIGN** — redefine inputs, estimand, operating characteristics, and engine before implementing the key.
- **DEPRECATE** — remove the key rather than expose a misleading calculation.
